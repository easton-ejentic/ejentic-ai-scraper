## Auth fail-open — important nuance

`proxy.ts` → `authConfigured()` returns **true** if `DATABASE_URL` is set. So the
fail-open behaviour only applies to **JSON dev mode**. In production (DATABASE_URL
set) auth is always enforced and `npm run db:seed` is mandatory. This is much less
risky than "auth fails open" sounds — worth saying precisely.

## Why .data/scraper.json needs a shutdown ordering rule

It is a write-whole-file JSON store with no transactions — the ordering rule is a
mitigation, not a design choice. The real answer to "why not a real database" is
that the Postgres path exists but is deliberately not switched on yet.
