# 2026-09-12

## Gap inventory: "what is left to implement"

Audited the codebase (not the status docs) to answer this. Findings, worst first.

### 1. The PostgreSQL path is incomplete — blocks real deployment

- `src/lib/production/postgresql-repository.ts:575` — `// TODO: Discover workflows
  and create/update in database`. `saveCrawlResult` stores company + evidence
  only; no workflows are ever derived on the Postgres path.
- `postgresql-repository.ts:701` — `generateAllStoredOpportunities()` is
  `return this.listStoredOpportunities()`. "Generate opportunities" is a **no-op**
  under Postgres.
- Same file has 39 `no-explicit-any`, including `return companies as any` /
  `return stored as any` — the domain mappers are cast-through, so type safety
  on the prod path is not real.
- No test covers any of this: all 162 tests run against the JSON backend.

### 2. Repository abstraction is bypassed in 8 places

These import `persistent-store` / `job-store` directly instead of
`getRepository()`, so they read a different store than the API writes to under
Postgres:

- pages: `scraper/control-center`, `scraper/jobs`, `scraper/jobs/[jobId]`,
  `scraper/logs`, `scraper/queue`
- API: `api/scraper/jobs/[jobId]`, `api/workflows/[workflowId]`,
  `api/workflows/[workflowId]/evaluate`

Works today only because JSON mode happens to share one file. Same class of bug
already fixed earlier in `api/companies/[companyId]` and
`api/opportunities/[opportunityId]`.

### 3. Mock data still ships (violates the "no fake data" constraint)

- `persistent-store.ts:78` — `jobs: clone(seedJobs)` from
  `src/lib/scraper/mock-data.ts`. A fresh install shows invented jobs.
- `scraper-control-center.tsx:11` — `workers` + `activityEvents` from mock-data.
  The "Workers" and "Live Activity" cards are fake.
- `scraper/sources/page.tsx` — the entire Sources page renders mock `sources`.
- `src/components/layout/placeholder-page.tsx` is now dead (0 usages) — delete.

### 4. Contact form delivers nowhere

`src/app/api/contact/route.ts` validates then `console.info`s. "Request access"
enquiries are lost unless someone tails stdout.

### 5. Integrations — deliberately NOT IMPLEMENTED

Salesforce, HubSpot, SMTP, Slack, outbound webhooks. Settings page states this
honestly (correct per the original brief: don't invent integrations).

### 6. No user-management UI

Auth supports ADMIN/OPERATOR/RESEARCHER/VIEWER and a Prisma `User` table, but
users can only be created via `npm run db:admin` (CLI) or `EJENTIC_USER_*` env
vars. No invite/create screen.

### 7. Ops

No Dockerfile (docker-compose.yml covers Postgres + Redis only), no CI, no
audit trail beyond activity logs.

### Notes for whoever picks this up

- Priority order if finishing: 1 → 2 → 3 → 4. Items 1 and 2 are the two that
  make "production mode" not actually production.
- Item 3 is the one a user is most likely to *see* (fake workers on the control
  centre, invented jobs on first run).
