repository-backed screens.

**Settings** — `/api/settings` (read-only, never returns secret values) +

## Pluggability into the main site (ejenticai.com)

- `src/lib/site-config.ts` — single source of truth: `siteConfig()`,
  `withBasePath()`, `stripBasePath()`.
- `next.config.ts` — `basePath` from `BASE_PATH`; framing policy swaps
  `X-Frame-Options: DENY` for `Content-Security-Policy: frame-ancestors 'self'
  <mainSiteOrigin>` when `ALLOW_EMBEDDING=true`.
- `src/proxy.ts` — base-path aware; redirect goes to `/app/login?next=...`
  not a bare `/login`.
- **Verified working**: built and ran with `BASE_PATH=/app`; `/app` 200,
  `/app/explore` 200, gated routes 307 → `/app/login?next=%2Fdashboard`,
  login + all dashboard routes and APIs 200 under the prefix.
- **GOTCHA (measured, not assumed): `BASE_PATH` and `ALLOW_EMBEDDING` are read
  at BUILD time.** Next.js bakes base path and `headers()` into the build
  output. Starting the server with a new value and no rebuild does nothing.
  Documented in `.env.example` and `docs/INTEGRATING_WITH_MAIN_SITE.md`.
- `ALLOW_EMBEDDING=true` + rebuild → confirmed
  `Content-Security-Policy: frame-ancestors 'self' https://ejenticai.com`.
- Sidebar is now `stripBasePath(usePathname())` so the active item still
  highlights under a prefix; sidebar + topbar show a "Back to main site" link
  when `NEXT_PUBLIC_MAIN_SITE_URL` is set.
- Topbar was hardcoded to "SE / Samuel" — now reads `/api/auth/session` and
  shows the real user + Sign out.

## Environment note

`npm run build` still needs `CODEBUDDY_SAFE_DELETE_ENABLED=0` or the sandbox
safe-delete shim blocks on a 50-file batch and hangs for 15–30 min. Purely
environmental — the build itself takes ~55s.

Also: `pkill -f "next start"` does not work here (Windows process names).
Free the port with PowerShell instead:

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
```

## Lint cleanup + final verification (continuation)

### Finished the React-compiler lint pass

All `react-hooks/*` errors are now gone (was 8, now 0). Fixes:

- `research/page.tsx` — replaced the mount effect with a `selectCompany(id)`
  click handler; `loadDossier` dropped from `useCallback` to a plain async fn
  since it is no longer an effect dep.
- `campaigns/page.tsx` and `opportunities/page.tsx` — removed `setLoading(true)`
  from `load()`. **Gotcha:** removing it was not enough for opportunities; the
  rule only stopped complaining once the body was wrapped in
  `try { ... } finally { setLoading(false) }` (same shape as campaigns). The
  compiler appears not to descend into a bare straight-line body the same way.
- `topbar.tsx` — `window.location.assign("/login")` → `router.replace("/login")`
  + `router.refresh()`. **This was a real bug, not just lint:** a hard assign to
  "/login" escapes `basePath`, so sign-out broke under sub-path mounting.
- `site-header.tsx` — scroll state now `useSyncExternalStore` (server snapshot
  `false`); mobile menu close is a render-time state adjustment keyed on
  `pathname` instead of an effect.
- `reveal.tsx` — IntersectionObserver support read via `useSyncExternalStore`.
  Server snapshot is `true` (assume observer runs) so SSR markup matches the
  first client render — using `false` made content paint visible, flip hidden on
  hydration, then fade in. The `<noscript>` rule in the marketing layout already
  covers the no-JS case.
- `faq.tsx` — dropped the `scrollHeight` ref read (refs during render). Height
  now animates via CSS `grid-template-rows: 0fr -> 1fr` with
  `[data-open="true"]`; inner wrapper needs `min-height: 0` or the row won't
  collapse.

Remaining: **39 errors, all `@typescript-eslint/no-explicit-any`** in
`postgresql-repository.ts` (32), `json-repository.ts` (5), `repository.ts` (2).
These are Prisma enum / `Json` bridge casts. Left alone deliberately — fixing
them means introducing a shared `EvidenceRecord` type and rewriting the domain
mappers on the Postgres path, which cannot be validated without a live database.

the top of the process environment, so the empty value won.
