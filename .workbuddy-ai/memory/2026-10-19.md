### Caveats found (real, verified)

1. **Prisma engine download can fail.** `@prisma/client`'s postinstall fetches engine
   binaries from the network. Plain `npm install` failed twice here with ECONNRESET on
   `@prisma/engines`. Environmental (this box blocks it), not a repo defect — worked
   around with `--ignore-scripts` + copying engines. On a normal PC with internet this
   is fine; behind a firewall/CI without it, install fails. Note: `@prisma/client` DOES
   have a postinstall, so `prisma generate` is automatic — no manual step needed.
2. **`--legacy-peer-deps` is no longer required.** README/RUNBOOK still say it is, but
   plain `npm install` resolved cleanly (no ERESOLVE) on npm 10.9.7. Harmless to keep;
   the advice is just stale.
3. **`.env.example` is a trap.** It ships a real-looking `DATABASE_URL`. Backend is
   chosen purely from whether that var is set, so `cp .env.example .env.local` without
   Postgres running breaks every data page. Also: with DATABASE_URL set, auth is on
   unconditionally (`authConfigured()` in `src/proxy.ts`) — but `db:seed` creates NO
   users, so you get locked out. Correct bootstrap is `npm run db:admin`.

### Fixes applied (commit 2ac5c21)

- README: removed `cp .env.example .env.local` from quick start, added warning about
  the DATABASE_URL trap; start with no `.env.local` (JSON mode).
- RUNBOOK: `npm run db:seed` → `npm run db:admin` in Postgres setup, plus an explicit
  note that db:seed is a data migration from the gitignored `.data/scraper.json`.
