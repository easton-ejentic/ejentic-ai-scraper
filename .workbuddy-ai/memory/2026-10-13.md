## Auth is DISABLED by default in local dev (non-obvious)

`src/proxy.ts` → `authConfigured()` returns true only if `DATABASE_URL` is set **or**
`EJENTIC_ADMIN_EMAIL`+`EJENTIC_ADMIN_PASSWORD` (or the `EJENTIC_USER_*` pair) are set.

So a fresh clone with no `.env.local` has **no login at all** — the dashboard is open.
Per `src/lib/auth/users.ts`, that is deliberate: auth reports `DISABLED` and the app stays
open rather than locking everyone out. `/api/health` surfaces it via `authStatus()`.

Consequences for a local run:
- To exercise the login flow, set `EJENTIC_ADMIN_EMAIL` / `EJENTIC_ADMIN_PASSWORD`.
- With `DATABASE_URL` set, auth is always "configured", so you **must** seed users with
  `npm run db:seed` or nobody can log in.
